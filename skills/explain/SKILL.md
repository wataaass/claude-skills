# explain

目標: ユーザーが面接でその変更を自分の言葉で説明できること。

**対象**: 引数で指定があればそれを、なければ会話中の最後の変更を対象にする。会話に変更がなければ `git diff HEAD~1` を見る。差分と前後数行だけ読み、ファイル全体は読まない。対象が大きければ、要の1〜3か所に絞り、残りは一覧だけ示す。

**解説**: 各か所について、結論から次の3点を書く（1か所15行程度まで。続きは求められたら書く）。
1. 何をしたか（1〜2文と、必要な行だけの引用）
2. なぜか（解決したかった問題と、その書き方を選んだ理由）
3. ほかの方法（現実的な別案1〜2個と、選ばなかった理由）

専門用語は初出で一言説明する。比喩は理解を助けるときだけ使う。

**確認**: 最後に「もし〜を変えたら？」のように理由を問う質問を2〜3問、質問機能（AskUserQuestion）でまとめて出す。使えなければ番号付きで並べる。答えには合っている点と足りない点を短く返し、間違えた点は別の角度から1回だけ説明し直す。
